## How to read this table

- **ID** — stable identifier, referenced from `dfd-level1.svg` arrows and from `evaluation/security/pen-test-report.md`.
- **Current Controls** — controls that exist **today** in this codebase (file/class-referenced). Nothing in this column is aspirational.
- **Residual Risk** — the risk that remains *after* the listed controls are applied. Honest ratings — several rows are Medium or High on purpose.
- **Acceptance Status** — `Accepted` (residual risk is understood and tolerated at current scale/threat environment), `Mitigated` (controls materially reduce risk and no further action is scheduled), `Needs Remediation` (a gap exists; tracked for a future sprint / ADR).

| THR-010 | Tampering | AI Config (Prompt Versioning) | Unauthorized or accidental push of a modified prompt template that alters agent behavior in production. | `PromptVersioningService` (immutable-once-published, SHA-256 content hash), `AdminRoleGateMiddleware` (ADMIN/SUPERVISOR-only) (`src/services/ai_config/`, `src/services/admin_portal/`). | Low | Accepted. |
| THR-011 | Tampering | Integration Platform (webhook registration) | Attacker with Admin Portal access (or a compromised admin session) tampers with a `WebhookRegistration` to redirect event delivery to an attacker-controlled URL, exfiltrating call/PII events. | `AdminRoleGateMiddleware` RBAC gate, `AuditMiddleware` mechanical mutation auditing (`src/services/admin_portal/`). | Medium | Needs Remediation — no explicit allow-list/SSRF validation of webhook target domains observed in `WebhookService`; recommend URL allow-listing. |
| THR-012 | Repudiation | AI Governance / Conversation Engine | An AI-driven decision (e.g. a settlement offer, a compliance block) cannot later be reconstructed or explained. | `ExplainabilityEngine` (`src/services/ai_governance/`), persisted `DecisionEnvelope`/`ResponsePlan` contracts, `AuditLogger` named wrappers for mandatory-coverage event types (Sprint-020). | Low | Mitigated. |
| THR-013 | Repudiation | Audit subsystem | A new domain event type is introduced without a corresponding `AuditLogger` wrapper, silently creating an audit blind spot. | `AuditEventType` enumerated catalog, `ComplianceMonitoring.SignalCorrelator` anomaly correlation (`src/services/compliance_monitoring/`). | Medium | Needs Remediation — coverage is enumerated by convention, not mechanically enforced at every call site (no boundary-checker rule requires new event types to route through `AuditLogger`). |
| THR-014 | Repudiation | Admin Portal | An administrator denies having performed a mutating action (e.g. tenant suspension, billing override). | `AuditMiddleware` (mechanical, controller code cannot opt out), hash-chained `AuditRepository` (Sprint-020/014). | Low | Accepted. |
| THR-015 | Repudiation | Policy Engine (break-glass) | `BreakGlassPolicy` usage bypasses normal policy evaluation without contemporaneous accountability. | `BreakGlassPolicy`/`BreakGlassDirective` mandatory audit event on invocation (`src/services/policy_engine/`). | Medium | Accepted — by design, break-glass trades preventive control for after-the-fact audit review; compensating control is mandatory post-hoc review, documented as an accepted residual risk. |
| THR-016 | Information Disclosure | All services (logging) | Raw PII (Aadhaar, PAN, phone, account numbers) leaks into application or infrastructure logs. | `StructuredLogger` unconditional `PIIRedactor` redaction on every log path (`src/libs/observability/logger.py`, Sprint-020), `scripts/check_pii_logs.py` CI gate. | Low | Accepted. |
| THR-017 | Information Disclosure | Repositories (Postgres) | Cross-tenant data leakage via a repository query that omits a tenant filter. | `TenantIsolationGuard` (AR-8), mechanically tenant-scoped `BaseRepository` subclasses, `TenantIsolationViolationError` raised on scope mismatch, verified in `tests/integration/services/test_tenant_isolation.py`. | Low | Accepted. |
| THR-018 | Information Disclosure | Event Bus / Redis (shared namespace) | Cross-tenant leakage via the shared Redis keyspace for tenants on the `SHARED` isolation profile. | `TenantProvisioner` Redis-namespace-per-tenant convention, key prefixing in `RedisClient` (`src/services/tenant_management/`, `src/libs/redis_client/`). | Medium | Needs Remediation — namespace separation is enforced by code discipline/key-prefix convention, not by Redis ACL/database-level hard isolation for `SHARED` tenants; `DEDICATED_CLUSTER` profile is the hard-isolation option but is opt-in. |
| THR-019 | Information Disclosure | LLM Runtime (Qwen2.5-7B via vLLM) | Repeated high-volume probing of the LLM/TTS endpoints to extract or distill model behavior/weights. | `APIRateLimiter` (per-tier), `UsageLimitEnforcer` (metering, Redis fast-path) (`src/libs/api_security/`, `src/services/metering/`). | Medium | Needs Remediation — rate limiting throttles raw volume but does not fingerprint distillation-style query patterns; no dedicated model-extraction detector exists. |
| THR-020 | Information Disclosure | Secrets management | Hardcoded credentials or leaked API keys/tokens committed to the repository or exposed in config. | `scripts/check_secrets.py` (regex + optional trufflehog CI gate), `SecretsManager`/`VaultProvider` (no plaintext secrets in code, Sprint-019), Vault Transit envelope encryption. | Low | Accepted. |
| THR-021 | Information Disclosure | Postgres (data at rest) | Database backup/snapshot exfiltration exposes customer PII in plaintext. | `EnvelopeEncryption`/`AESGCMEncryptor` for PII columns (`customers.*_encrypted`), `CryptoShredder` for erasure-on-demand (`src/libs/encryption/`, Sprint-019). | Low | Accepted. |
| THR-022 | Denial of Service | GPU Scheduler (VRAM ledger) | Burst of legitimate-looking inference requests exhausts GPU VRAM, starving concurrent calls. | `VRAMLedger` + `AdmissionController` (RI-8: reject-not-queue-to-OOM), `GPUFailureStrategy` failover to healthy device (`src/services/gpu_scheduler/`, `src/libs/recovery/`). | Medium | Mitigated — admission control guarantees no OOM-by-construction, but a sustained flood of admissible requests still degrades service via REJECTs; capacity planning (Volume 7) is the complementary control. |
| THR-023 | Denial of Service | Media Gateway (RTP ingress) | Volumetric RTP packet flood against the media plane, independent of session/auth state. | `ConnectionAuthenticator` auth-before-allocation (AR-2) limits *session* creation; `NetworkPolicy` deny-all baseline (Sprint-026) limits reachable ports. | High | Needs Remediation — no perimeter rate-limiting/SBC-level flow control observed ahead of the application layer; raw packet flood mitigation is out of scope for the current architecture and needs a dedicated DDoS-protection ADR before GA. |
| THR-024 | Denial of Service | LLM Runtime | Adversarial input crafted to induce runaway token generation ("token bomb"), inflating latency/cost and starving the shared vLLM instance. | Bounded `max_tokens` in `vLLMAdapter`/`PromptContract` streaming calls (`src/services/llm_runtime/`). | Medium | Needs Remediation — a global `max_tokens` bound exists, but no per-tenant token-budget circuit breaker specifically targeting token-bomb patterns is implemented. |
| THR-025 | Denial of Service | Public API / Admin Portal | WebSocket or REST flood against externally reachable endpoints. | `APIRateLimiter`, `CircuitBreaker` (`src/libs/circuit_breaker/`), `BoundedQueue`/`LoadShedder`/backpressure (Sprint-016). | Low | Mitigated. |
| THR-026 | Denial of Service | Event Bus (Redis Streams consumers) | Slow or stalled consumer causes stream backlog growth, eventually exhausting Redis memory. | `BoundedQueue`, `DLQHandler`, `EventRouter`, `WorkerPool` (`src/libs/event_bus/`, `src/libs/concurrency/`). | Low | Mitigated. |
| THR-027 | Elevation of Privilege | Admin Portal | Non-admin user escalates to ADMIN-level access via a route that lacks the role gate. | `RBACEngine` + `ROLE_PERMISSIONS`, `AdminRoleGateMiddleware` (ADMIN/SUPERVISOR-only, mechanically wraps every Admin Portal route) (`src/services/authz/`, `src/services/admin_portal/`). | Low | Accepted. |
| THR-028 | Elevation of Privilege | AuthZ / Tenant Management | A tenant-scoped user performs an action outside their tenant, effectively escalating to cross-tenant or platform-admin privilege. | `TenantIsolationGuard`, `ABACEvaluator`, `OrgHierarchy.resolve_scope()` (`src/services/authz/`, `src/services/org_management/`). | Low | Accepted. |
| THR-029 | Elevation of Privilege | AuthZ (JIT privilege) | A time-bounded `JITGrant` is not revoked promptly, leaving a standing elevated-privilege window longer than intended. | `JITPrivilege`/`JITGrant` (time-bounded, expiry checked at evaluation time), `AuditLogger` records grant/use (`src/services/authz/`). | Medium | Mitigated — expiry is enforced at evaluation time; there is no proactive revocation notification/alert when a grant is nearing or past expiry, only reactive denial. |
| THR-030 | Elevation of Privilege | Policy Engine | Crafted request bypasses PDP evaluation entirely (e.g. missing policy lookup call on a new code path), effectively self-granting a privileged action. | `PolicyEngine` PDP (Redis cache → Postgres fallback → deny-override → audit), `AIGovernancePolicyPack`/`AuthorizationPolicyPack` `hard_rule=True` rules (`src/services/policy_engine/`). | Low | Accepted — deny-override default means a missing/failed lookup denies rather than silently permits. |
