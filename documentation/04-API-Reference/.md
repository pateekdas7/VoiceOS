## 1. Base URL & versioning

- **Base:** `https://api.voiceos.example/{version}` — version is URL-path (V6 API-DS-3): `v1` current.
- **Versioning policy.** Backward-compatible within a version (additive only); breaking changes → new version + ≥12-month deprecation window (V5 Ch16). Deprecated versions return a `Sunset` header.
- **White-label.** Partner tenants may use custom domains (V5 Ch20); the API contract is identical.

## 2. Authentication

Every endpoint authenticates (V4 Ch5) and authorizes (V4 Ch6) with tenant scoping (AR-8); only health checks are unauthenticated.

- **OAuth2** (bearer): `Authorization: Bearer <token>` — for user/partner apps.
- **API key**: `Authorization: ApiKey <key_id>:<secret>` — for server-to-server; keys are vaulted + rotatable (V4 Ch7), scoped (least privilege).
- **mTLS** for internal/enterprise service-to-service (V4 Ch5).

```http
GET /v1/campaigns HTTP/1.1
Host: api.voiceos.example
Authorization: Bearer eyJhbGciOi...
```

**Auth errors:** `401 AUTH_REQUIRED` / `AUTH_INVALID` / `TOKEN_EXPIRED`; `403 FORBIDDEN` / `TENANT_MISMATCH`.

## 3. Standard headers

| Header | Direction | Purpose |
|---|---|---|
| `Authorization` | request | auth (§2) |
| `Idempotency-Key` | request | required on state-changing effects (API-DS-4 / AR-15) |
| `X-Request-Id` | both | request correlation (echoed; ties to trace, V3 Ch17) |
| `X-Tenant-Id` | request (server-to-server) | tenant scope (else derived from token) |
| `Content-Type` / `Accept` | request | `application/json` |
| `X-RateLimit-Limit` / `-Remaining` / `-Reset` | response | rate-limit state (§7) |
| `Sunset` | response | deprecation date (versioning) |

## 4. Conventions (REST)

- Resource-oriented, plural nouns; `snake_case` JSON matching `libs/contracts` (V6 Ch5).
- Money as `{amount_minor, currency}` (never float); timestamps ISO-8601 UTC.
- GET is side-effect-free; POST creates/acts; PATCH updates; DELETE removes.
- Collections paginate (cursor-based, §6). All requests schema-validated (`extra: forbid`, API-DS-2).

## 5. Uniform response & error shape

**Success:** the resource (or `{ items, next_cursor }` for collections).
**Error (uniform, no internal leakage — V6 Ch5):**

```json
{ "error": {
    "code": "PTP_DATE_INVALID",
    "message": "promised_date must be in the future",
    "request_id": "01J...",
    "details": []
} }
```

**Standard status codes:** `200/201/204` success · `400` validation · `401/403` authn/authz · `404` not found · `409` conflict · `422` unprocessable · `429` rate limited · `5xx` server. Error `code`s are stable enums (per-resource lists below).

## 6. Pagination

Cursor-based (stable under inserts): `GET /v1/{collection}?limit=50&cursor=<opaque>` → `{ "items": [...], "next_cursor": "<opaque|null>" }`. `limit` bounded (default 50, max 200).

## 7. Rate limiting

Per-tenant + per-key limits + quotas (V4 Ch12 / V3 Ch4), policy-driven (AR-7, not hardcoded). On exceed: `429` + `Retry-After` + `X-RateLimit-*` headers. Enterprise tiers get dedicated limits (V5 Ch22).

## 9. WebSocket / Streaming APIs

Real-time channels (V5 Ch16 / V1 for media); authenticate on connect, authorize the session, validate every frame (V4 Ch12), bounded message size + per-connection rate limits, backpressure-aware (RI-3).

- **Live call events:** `wss://api.voiceos.example/v1/stream/calls/{call_id}` — streams typed events (`call.connected`, `turn.completed`, `ptp.captured`, `call.ended`). Typed envelope with a `type` discriminator; versioned like REST.
- **Media (internal/runtime):** the runtime media path (RTP/TTS WS, V1 Ch3/Ch17) is internal, not a public API; documented here only for completeness — see V1.

```text
→ connect (Authorization on upgrade)
← { "type": "call.connected", "call_id": "...", "v": 1 }
← { "type": "turn.completed", "turn_index": 3, "outcome": "ptp_discussed", "v": 1 }
← { "type": "ptp.captured", "ptp_id": "...", "v": 1 }
```

## 10. Webhook events (outbound)

Subscribe to platform events (V5 Ch15/16); delivery is signed (HMAC), retried with backoff → DLQ (V3 Ch10). Subscriptions are tenant-scoped.

- **Subscribe:** `POST /v1/webhooks` `{ "events": ["ptp.captured","call.ended"], "target_url": "...", "secret_ref": "..." }`
- **Delivery headers:** `X-VoiceOS-Signature` (HMAC of body), `X-VoiceOS-Event`, `X-Request-Id`.
- **Event names** follow the event contract (V6 EV-2, `<aggregate>.<event>`, past tense). Common events:

| Event | When |
|---|---|
| `call.connected` / `call.ended` | call lifecycle |
| `ptp.captured` / `ptp.broken` | promise-to-pay |
| `settlement.recorded` | settlement |
| `campaign.completed` | campaign finished |
| `report.ready` | async report generated |

```json
// webhook POST body (signed)
{ "event_type": "ptp.captured", "schema_version": 1, "tenant_id": "...",
  "occurred_at": "2026-...", "payload": { "ptp_id": "...", "amount_minor": 500000 } }
```

**Consumer rules:** verify the signature; be idempotent (dedup by `event_id`); tolerate unknown fields (forward-compat, EV-5); respond `2xx` quickly (process async).

## 11. SDKs

Generated from `apis/openapi` (no hand-written drift): Python, Java, Node, .NET (V5 Ch16). SDKs wrap auth, retries (idempotent), pagination, and typed models.

## 12. Error code index (cross-resource)

| Code | HTTP | Meaning |
|---|---|---|
| `AUTH_REQUIRED` / `AUTH_INVALID` / `TOKEN_EXPIRED` | 401 | authentication |
| `FORBIDDEN` / `TENANT_MISMATCH` | 403 | authorization / isolation |
| `NOT_FOUND` | 404 | resource missing |
| `VALIDATION_FAILED` | 400/422 | schema/field validation |
| `PTP_DATE_INVALID` / `OUT_OF_ENVELOPE` | 422 | collections business rules |
| `OUTSIDE_WINDOW` | 422 | RBI calling window (V4 Ch2) |
| `APPROVAL_REQUIRED` | 409 | human approval needed (V4 Ch15) |
| `ENTITLEMENT_DENIED` | 403 | plan/entitlement (V5 Ch9) |
| `DETERMINISM_VIOLATION` / `SAFETY_BLOCK` | 422 | AI-config governance (V5 Ch14 / V4 Ch14) |
| `RATE_LIMITED` | 429 | rate limit (§7) |
| `CONFLICT` | 409 | state conflict |
| `INTERNAL` | 500 | server error (no internal detail leaked) |
